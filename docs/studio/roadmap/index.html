Where this is going

SeasonStudio today is eight generators sharing a window. The direction of travel is a studio that remembers what you did, helps you say what you want, and can carry out a whole piece of work rather than one step of it.

How to read this page

Four horizons, ordered by confidence rather than by date. Horizon 0 is in your hands now. Horizon 1 is what we are building. Horizon 2 is where we intend to go. Horizon 3 is honest speculation. Nothing here carries a delivery date, because a roadmap with dates is a marketing document.

Horizon 0 · Shipped Horizon 1 · Next Horizon 2 · Then Horizon 3 · Later Not planned

Horizon 0 · Shipped In the app

The ground the rest of this page stands on. Eight modalities, two local inference stacks, two content safety gates, and no account anywhere.

Eight tools in one shell

Text, translation, image, video, music, transcription, speech and vision, sharing one layout, one results panel and one set of habits.

Entirely on device

llama.cpp, stable-diffusion.cpp, GGML and ONNX Runtime, with CUDA, DirectML, Vulkan, Metal and CoreML where the hardware offers them.

Only what this run needs

A run names the single file it is missing. No pre-provisioning, no model zoo you did not ask for.

Windows and macOS

One codebase, built on the same SeasonEngine foundation as its sister application, shipping through both desktop stores.

Horizon 1 · Next In progress

Making a good afternoon repeatable.

The gap we hear about most is not a missing modality — it is that a lucky result is hard to get back to. This horizon is about memory, guidance and the small editing moves that currently send you to another application.

Workflows you can reopen

Every run saved locally with its model, prompt, seed and settings, so a result can be reopened, adjusted and re-run weeks later. Today the studio shows you only what the current run needs; the intent is a history you can walk back through, entirely on your own disk. This is the single most requested thing, and the first thing we are building.

A model manager inside the app

One place to see what is on your shelf, how much space it takes, which panel it belongs to and what its licence permits — instead of reasoning about a folder of large files.

Prompt assistance

Describe what you want in ordinary sentences and let the local language model turn it into a prompt shaped for the model you actually chose. The Text panel can already do this by hand; the point is to make it part of the panel you are standing in.

Light image and audio editing

Crop, straighten, adjust levels, trim a clip, fade an edge. Not a photo editor and not a sequencer — just enough that a finished result does not need a round trip through another application before you can use it.

Presets and batches

Save a configuration you like as a named preset, and run a prompt across several seeds or several sizes in one go, so exploring costs one decision instead of ten.

Horizon 2 · Then Planned

One sentence, a whole piece of work.

Today you drive eight tools. In this horizon the studio can drive them for you: you describe the outcome, and a local agent plans the steps, moves material between panels, and comes back with something whole for you to judge.

A local agent that carries out a task

"Make me a thirty-second opener for a storybook video: three illustrations in one style, a narrated line over each, and an ambient bed underneath." The agent decomposes that, picks models, runs the panels in order, and presents the result with every step visible and re-runnable. Running on your machine, on your shelf, with nothing dispatched anywhere.

Material that flows between tools

A transcript straight into Text, a caption from Vision straight into Image, a finished still straight into Video, a script straight into speech. Today that is copy and paste; it should be one action.

A project shelf, not just a model shelf

Characters, palettes, reference images, voices and recurring style notes, kept per project and reusable across every panel — so a series looks like a series without you re-typing its identity each time.

3D generation

Mesh from a prompt or from a reference image, exported in formats the rest of your pipeline already reads. This is the point where the sister engine becomes more than a shared foundation: SeasonEngine renders glTF natively, so a generated asset has somewhere to go the moment it exists.

Storyboards and sequences

Panels in order, with consistent characters and a shared palette, so image generation can serve narrative work rather than single frames.

Horizon 3 · Later Exploring

A design suite, if the field keeps moving.

Everything below depends on models that either do not exist yet or do not yet fit on a desktop. We list it because it is the direction we are steering, not because it is promised.

Animation binding

Rigging and motion for a generated mesh: a skeleton inferred automatically, weights fitted, and a clip driven from a description or a reference. Together with 3D generation this is the longest-standing item on our own list, and the one that would most change what the studio is for.

An optional cloud bridge

Some work needs a model that will never fit on a laptop. If we add the ability to send a single run to a hosted API, it will be opt-in per run, off by default, clearly marked while it is happening, and never a requirement for anything the app does today. Local first is not a phase we are passing through — it is the product.

iOS and Android

The codebase already targets mobile; the constraint is that phone-class hardware suits some of these panels and not others. A mobile release would start from the tools that genuinely work there rather than pretending the whole studio fits.

Export paths and extension points

Cleaner hand-offs to the tools designers already use, and a way to add your own step to a workflow. Shape to be determined by what people are actually doing with the app.

A straight line to the engine

Generated assets — textures, meshes, animations, audio — dropping into a SeasonEngine project without a conversion step. Two applications, one foundation, and the sister relationship finally doing some work.

Not planned

A roadmap is more useful when it also says what will not happen. These are decisions, not omissions.

  • A subscription. Premium is a one-time unlock and will stay one.
  • An account system. There is nothing to sign into, and nothing worth adding one for.
  • Telemetry or analytics. Not now, not behind a toggle, not "anonymised".
  • A mandatory cloud path. If a hosted option ever appears it will be optional, per run, and off by default.
  • Uploading your work anywhere. No gallery, no community feed, no sync service.
  • Training on your data. We never receive it, so the question does not arise.
  • A node-graph interface. Excellent tools already exist for that audience. This one is for people who want the shortest path from a sentence to a file.
The studio should get better at understanding you, not better at collecting you. — the line we check new features against
