Post-processing and compute effects

Bloom, TAA, GTAO, the sky LUTs and the debug views are not hard-wired stages. They are compute effects registered against a frame phase, and the twenty-line contract that carries them is the same one your own effect implements.

What ships in the box

Effects live in Rendering/Effects/. Each one registers into a compute phase, declares the textures it produces, and can be inspected as a 2D sprite by name — which is how the reference application's debug mode works.

TypePhasePurpose
BloomEffectAfterSceneDownsample / upsample chain over HDR scene colour.
GtaoEffectAfterSceneAmbient occlusion for indirect diffuse.
TaaEffectAfterSceneJittered temporal resolve with variance clipping and sharpening.
MotionBlurEffectAfterSceneCamera and object streaks gathered along the velocity buffer.
DdgiEffectAfterSceneProbe tracing and irradiance atlas update.
SkyAtmosphereEffectFrameStartScattering LUTs, cloud noise and the aerial volume.
SceneColorCopyEffectAfterSceneA readable snapshot of scene colour for effects that need it.
DepthViewEffectAfterSceneLinearised depth as an inspectable texture.
VelocityViewEffectAfterSceneMotion vectors, visualised.
Sdf3DViewEffectFrameStartSlice through a signed distance field of the kind DDGI traces.
PlasmaEffectFrameStartA minimal compute example — the one to copy when writing your own.

Any of them can be put on screen with three lines, because effect outputs are addressable textures:

AddControl(new Sprite2D
{
    Name = Season.Rendering.Effects.GtaoEffect.TextureName,
    Color = Colors.White,
    PosX = 20, PosY = 580, Width = 240
});

Names follow one scheme: compute:// for 2D textures and compute3d:// for volumes. GTAO publishes compute://gtao/ao, the sky publishes compute://sky/skyview and compute3d://sky/aerial, and the plasma sample publishes compute://plasma. Nothing about consuming them is special — a Sprite2D or a material override takes the name and that is the whole interface.

The effect contract

ComputeEffect is an abstract class with five members. That is the entire extension surface. 

public abstract class ComputeEffect
{
    public abstract string Name { get; }
    public abstract ComputePhase Phase { get; }

    // Create textures and pipelines. Return false and the effect is
    // dropped with nothing left behind.
    public abstract bool Initialize(IGraphics g);

    // Dispatch. Called once per frame, in phase order.
    public abstract void Record(IGraphics g);

    // Swapchain changed size. Recreate anything resolution-dependent.
    public virtual void OnResize(IGraphics g) { }
}
Contract

Initialize returning false must leave no residue — no half-created textures, no dangling names in FrameSchedule. That is what makes an effect genuinely optional: a backend without compute support and a user who switched the effect off produce the same, correct frame.

Writing a compute effect walks through PlasmaEffect line by line.

Bloom

A threshold-and-knee soft clip followed by a six-level downsample and upsample chain over HDR scene colour. Because scene colour is genuinely HDR, the threshold means something: it selects pixels brighter than white rather than pixels that happened to clip.

SettingDefaultMeaning
BloomEnabledonOff skips the chain and clears FrameSchedule.BloomTexture.
BloomThreshold1.0Radiance above which a pixel contributes.
BloomKnee0.5Softness of the threshold, so the bloom fades in rather than switching on.
BloomIntensity0.3How much of the chain is added back.
BloomMipCount6Chain depth. More levels means a wider, softer glow.

Anti-aliasing: four tiers, honestly labelled

AaMode has four values and they are not four qualities of the same thing — they operate in different colour spaces at different points in the frame.

ModeWhere it runsNotes
Off—No filtering.
Msaa4xRasterLegacy tier, D3D12 only. HDR resolve quality is compromised and bandwidth cost is high; it stays as a VR fallback.
FxaaPost-tonemap LDRFXAA 3.11, applied in the Post composite and at FinalBlit. Cheap and universal.
TaaHDR, before tonemapDefault. Needs velocity and compute; selecting it forces MotionVectors on at initialization. Falls back to Fxaa where unavailable.

TAA is implemented and stabilised on D3D12, Vulkan, Metal and WebGPU. The fallback to FXAA is automatic rather than an error, which means a scene requesting TAA still renders on a device that cannot deliver it — softer, but rendered.

TAA in detail

The camera jitters the projection matrix by a sub-pixel offset each frame, the resolve reprojects the previous result through motion vectors, and variance clipping decides how much of the history to trust. The interesting part is that both the jitter and the history live on Camera3D, where you can read them.

SettingDefaultMeaning
MotionVectorsonWhether the Scene pass writes velocity. TAA forces it.
JitterPhaseCount7Length of the jitter sequence before it repeats.
JitterScale1.0Jitter amplitude in pixels. Above 1 trades stability for coverage.
TaaFeedback0.9History weight for moving pixels.
TaaStaticFeedback0.97History weight where nothing moved — more history, more resolve.
TaaVarianceClipGamma1.0How tightly history is clamped to the neighbourhood. Lower is more ghost-resistant and more aliased.
TaaSharpness0.5Post-resolve sharpening, because temporal accumulation softens.
On Camera3DWhat it is for
ProjectionJitteredThe projection actually used to render, jitter included.
PrevViewProjectionLast frame's matrix, which is what makes reprojection possible.
JitterNdc, JitterPixelsThis frame's offset, in both spaces.
UpdateTemporal, ResetTemporalAdvance the sequence, or discard history after a camera cut.
Call ResetTemporal after a teleport

Reprojecting across a discontinuous camera move smears the old frame across the new one for as long as the feedback weight takes to decay. Cutting the camera is exactly the case motion vectors cannot describe.

Motion blur

One gather kernel over the velocity buffer the engine already writes for TAA, at full resolution in linear HDR and before tone mapping. It reads the image TAA resolved, this frame's velocity and depth, and publishes compute://motionblur as the new head of the scene chain.

Registration order is execution order, and the reference application registers it after TaaEffect and before BloomEffect. After the resolve, because blurring before it would feed a smeared image into the history and smear the subpixel jitter along every streak. Before bloom, because a highlight that was streaked has to be the highlight bloom sees — the other order leaves a hard-edged glow floating over a blurred body.

SettingDefaultMeaning
MotionBluronOff at startup registers nothing and allocates no texture; switched off at runtime it stands down on the next frame and revokes only its own publication.
MotionBlurSamples12Taps along the streak. The loop bound is a parameter, clamped to 4..32 rather than trusted.
MotionBlurShutter0.5Fraction of the velocity vector integrated. Zero is a clean bypass, not a blur of zero length.
MotionBlurMaxRadius0.04Cap on the streak length as a fraction of frame height, so a fast pan cannot smear the frame into soup.

Velocity is the surface's displacement from the previous frame to this one — the same convention TAA reprojects with — so the gather walks forwards along it. Tap t reads the colour that was here when the shutter opened, which is now found further along the motion, and t = 0 lands on this pixel. The streak therefore trails behind whatever moved. Each tap is weighted by a relative depth difference, so a streak cannot pull a foreground silhouette into the background or dissolve one into the other.

Only passes that carry a velocity attachment write velocity. Water, the waterfall, the river ribbon, decals, the Overlay pass and every 2D and text path write none, so they stay sharp — which for text is the outcome you want.

Depth of field

One gather kernel that turns the circle of confusion implied by a thin lens into a bokeh disc, in linear HDR and after the TAA resolve. It reads the resolved scene colour and the explicit single-sampled SceneDepth, and publishes compute://dof as the third head of the scene chain.

Registration order is execution order: after MotionBlurEffect, so a moving highlight is gathered once instead of once per tap, and before BloomEffect, so the bloom chain sees the final defocused highlights rather than a sharp glow floating over a soft body.

SettingDefaultMeaning
DepthOfFieldoffOff registers nothing and allocates no texture. Gather is the 24-tap disc. The tier is read at registration, so switching it on needs a restart; switching it off stands the registered effect down on the next frame.
DofAperture1.4f-number the main camera starts with. The effect itself reads Camera3D.Aperture every frame, so a scene that points its own lens still wins.
DofFocusDistance6Startup focus distance in metres. Same split: the live value is Camera3D.FocusDistance.
DofMaxCoCRadius0.02Hard cap on the blur radius as a fraction of frame height, about 22 px at 1080p. The disc area is the cost and the tap budget is fixed, so this is a ceiling rather than a taste dial; anything above 0.05 is clamped.

The circle of confusion is the thin-lens one, computed per sample from the loaded depth: c = f² / (N (F − f)) · |z − F| / z, with the sensor height derived as 2 f tan(FovY / 2), so focal length and field of view stay two independent numbers. Focus is a per-camera lens quantity: it does not dirty the view or projection matrices, and a rack focus is a plain runtime write to Camera.FocusDistance. There is no autofocus and no focus-pull easing.

Only opaque geometry writes depth, so transparent passes — particles, the water surface, the Overlay pass and every 2D and text path — are focused by whatever surface sits behind them. A secondary view pays nothing unless ViewFeature.DepthOfField is added to it, which is why the minimap and the rear mirror stay sharp.

Colour grading

Not an effect. Grading rides the constant block every backend already uploads for the tonemap, so there is nothing to register, nothing to allocate and no pass to schedule. It lives inside the same Tonemap() that converts HDR to display-referred sRGB, which is also why both the post pass and the direct-to-backbuffer blit get it without a second code path.

The order is fixed and deliberately photographic: white balance, ASC CDL lift/gain, gamma, contrast about mid-grey, saturation against Rec.601 luma, then a single strength that mixes the result back over the ungraded image. Every step is guarded by a uniform comparison against its own identity value, so Neutral walks the whole function and still has to reproduce its input bit for bit — that is what makes it a control you can measure against rather than a subtle look.

PresetCoefficientsIntent
OffnoneDefault. The shader branch is skipped entirely, so the image is bit-identical to the pipeline before grading existed.
Neutralall identityThe lossless control: full code path, no deviation.
WarmFilmcontrast and saturation up, warm white point, lifted blackLate-afternoon film print.
CoolTealstronger contrast, cool white point, slightly crushed gammaNight exteriors and underwater distance.
Monosaturation 0, contrast and lift raisedA full desaturation that keeps the blacks from going flat.

Two persisted settings, both live on the next frame because the coefficients are re-read whenever the constants are uploaded: ColorGrade names the preset and ColorGradeIntensity scales the whole result, so a shot can fade a look in without editing the table. A scene that wants its own numbers calls ColorGrading.Lookup; the file only ever stores the name, because half a preset written into Settings.json would make the panel and the image disagree.

Where it runs: D3D12 root constants (b0, slots 8–15), Vulkan push constants (floats 7–14), Metal BlitParams (bytes 32–63) and the WebGPU tonemap uniform array — the same eight floats in the same order everywhere.

The other three backends share the maths and compile, but only D3D12 has been photographed. Known gaps

  • Partial GTAO is a lite variant. Half-resolution horizon-based AO with depth-reconstructed normals, interleaved-gradient noise and a depth-aware blur. It is not full ground-truth AO, and the name is inherited from the technique family rather than claiming the reference implementation.
  • Partial Motion blur is a centre-velocity gather. It does not dilate the velocity neighbourhood the way a tiled implementation does, so an object smaller than its own displacement dims instead of leaving a long tail. Geometry drawn without a velocity attachment does not blur at all.
  • Partial Depth of field is a fixed 24-tap gather. A larger radius spreads the same taps thinner, so past roughly 0.03 of frame height the bokeh starts to ring rather than soften; that is why the cap exists. It also has no scatter-as-gather, no half-resolution path, and no autofocus.
  • Absent Chromatic aberration and 3D LUT files. Grading itself is parameter-based, as above — a look is seven numbers, not a cube. Importing a .cube or any sampled LUT would need a sampler and a 3D-texture path the blit pass does not have.
  • Absent Upscalers. No FSR, DLSS or temporal upscaling. TAA resolves at native resolution.
